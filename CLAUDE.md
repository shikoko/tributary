# Working on Tributary

## Commits and pull requests

- **No attribution lines, anywhere.** No "Co-Authored-By: Claude", "Claude-Session:", "Generated with Claude Code", "Generated by Claude Code" or similar, in commit messages, pull request titles or descriptions, or comments. `.claude/settings.json` turns off the ones Claude Code adds by itself.
- **Always remove the "Generated by Claude Code" footer.** A pull request opened or edited from a Claude Code cloud session gets a `---` line and "_Generated by [Claude Code](…)_" added to the end of its description, and it comes back after every edit made from there. The **Tidy pull requests** workflow (`.github/workflows/tidy-pull-requests.yml`) removes it within a minute. After opening or editing a pull request, check that the footer is gone; if it isn't (the workflow didn't run), remove it from a session that can edit the description without it coming back, or ask the maintainer to.
- **Commits are the maintainer's.** Author and committer are the repository's owner, never Claude, and commits from a cloud session aren't signed with the session's key.
- **Branches:** make a branch from `develop` for each change and open a pull request into `develop`. `main` only changes through a pull request from `develop`. Releases are built from `main` (see `docs/development.md`).
- **Every pull request is merged with a merge commit**, into `develop` and into `main`: never "Squash and merge" or "Rebase and merge", which copy the commits and leave the branch looking unmerged in the graph.
- **Rebase before merging:** before merging a pull request into `develop`, rebase its branch onto the latest `develop` and push it (`--force-with-lease`), so the branch starts from the tip of `develop` and the graph shows a short loop that joins straight back in. A pull request from `develop` into `main` isn't rebased.

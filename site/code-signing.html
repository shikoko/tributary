Code signing policy

How Tributary's downloads are signed, who decides what gets signed, and what Tributary connects to once it's installed.

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Being set up. Signing the Windows downloads with SignPath Foundation's certificate is being set up. Until it's in place, the Windows downloads aren't code-signed, and each release's notes say how to open Tributary the first time.

What gets signed

The Windows downloads: the setup (_x64-setup.exe and _arm64-setup.exe), the installers inside it, and the Tributary program and its uninstaller that they install.

Only files built from the source code in Tributary's repository are signed, built by its release workflow on GitHub's own machines (GitHub Actions). Nothing built on anyone's own computer is signed, and nothing from anywhere else: Tributary doesn't include other people's programs in its downloads.

How a release is signed

  1. Every change reaches the released code through a pull request, which the maintainer reviews before it's merged.
  2. A release starts when the maintainer merges a release pull request into main. GitHub Actions builds it there, from that commit's source code.
  3. The build sends the Windows files to SignPath, and the maintainer approves the signing for that release. Nothing is signed without that approval.
  4. The signed files are published on the releases page, with the update file that copies of Tributary already installed update from.

Every download, on every system, also comes with an attestation: a record, signed by GitHub, of the repository, commit and workflow it was built by. With the GitHub CLI, check a file you downloaded like this:

gh attestation verify Tributary_0.18.0_x64-setup.exe -R shikoko/tributary

Privacy

Tributary has no analytics, no crash reporting and no account of its own, and it sends nothing to the project or its maintainer. It only connects to:

  • your repositories' remotes, through your own git, when you fetch, pull, push or clone (and in the background, if Fetch in the background is on);
  • GitHub, to check for updates, if Check for updates automatically is on, or when you ask it to;
  • GitHub's or GitLab's API, for the pull requests and checks of repositories hosted there, and when you sign in;
  • the issue tracker you set up for a repository, if you set one up;
  • GitHub, GitLab and Gravatar, for profile pictures, while Profile pictures is on.

The privacy notice lists exactly what's sent in each case, and what Tributary keeps on your computer.

Something wrong?

If you find a file signed for Tributary that didn't come from its releases page, or anything else here that doesn't add up, please report it privately, as the security policy describes.
